# NextLink Elective Schedule Plan

ระบบวางแผนตารางสอนวิชาเลือก ภาควิชาวิศวกรรมคอมพิวเตอร์ จุฬาฯ

แต่ละบริษัทที่เสนอวิชามาแจ้ง "ช่วงที่สะดวกสอน" ไม่เท่ากัน — บางบริษัทว่างพุธเช้า
ช่วงเดียว บางบริษัทว่างทั้งพุธเช้าและศุกร์เย็น ระบบนี้จัดตารางโดยล็อกวิชาที่มี
ทางเลือกน้อยที่สุดก่อน แล้วปัดวิชาที่ยืดหยุ่นกว่าไปช่วงอื่น พร้อมดูแลเรื่องห้อง
ที่ใช้ได้ไปพร้อมกัน

## Tech stack

- Next.js 15 (App Router) + React 19 + TypeScript
- ไม่มีฐานข้อมูล — ข้อมูลตั้งต้นเป็น JSON และแผนที่แก้ไว้เก็บใน `localStorage`
- ไม่มี dependency นอกเหนือจาก Next/React

## เริ่มใช้งาน

```bash
npm install
npm run dev        # http://localhost:3000
```

## ตารางเวลา

จันทร์–เสาร์ × 3 คาบ = 18 คาบต่อห้องต่อสัปดาห์

| คาบ | เวลา |
| --- | --- |
| เช้า | 09:00–12:00 |
| บ่าย | 13:00–16:00 |
| เย็น | 16:00–19:00 |

คาบบ่ายกับคาบเย็นต่อกันพอดีที่ 16:00 — ดู `docs/data-model.md` ว่าทำไมเรื่องนี้
ถึงสำคัญกับการตรวจว่าเวลาทับกัน

## ห้องเรียน

**ใช้ได้ทันที (จุฬาพัฒน์)** — จุฬาพัฒน์ 4 ชั้น 1 (64), โถงกลาง ชั้น 3 (236),
ห้อง A ชั้น 3 (64), ห้อง B ชั้น 3 (30), จุฬาพัฒน์ 5 ห้อง 203 (58) และ 206 (36)

**ต้องขออนุมัติก่อนใช้ (คณะวิศวะ)** — ตึก 4 ห้อง 17-02 (~40), ตึก 4 ห้อง 18-15
(~30), ตึก 3 ห้อง 405 (~50)

ตัวเลขที่มี `~` มาจากวิชาที่เคยใช้ห้องนั้น ยังไม่ได้ยืนยันกับผู้ดูแลอาคาร ระบบ
ถือเป็นขอบล่างและจะไม่จัดวิชาที่รับเกินตัวเลขนี้ลงไป

ระบบจะ **ไม่จัดวิชาลงห้องคณะวิศวะเลย ถ้าห้องจุฬาพัฒน์ยังรับไหว** และวิชาที่ตก
ไปอยู่ห้องคณะวิศวะจะขึ้นเตือนว่าต้องยื่นเรื่องขอใช้ห้อง

## การจัดตารางอัตโนมัติ

`planSchedule()` ใน `lib/scheduler.ts` เป็น pure function — ไม่มีนาฬิกา ไม่มี
random รันซ้ำด้วย input เดิมได้ผลเดิมทุกครั้ง

1. คาบที่ผู้ใช้ล็อกไว้ถูกยึดไว้ก่อน และจะไม่ถูกย้ายไม่ว่ากรณีใด
2. เรียงวิชาแบบ **most-constrained-first** — วิชาที่มีทางเลือกเหลือน้อยที่สุด
   จัดก่อน นี่คือกลไกที่ทำให้บริษัทที่ว่างคาบเดียวได้คาบนั้นเสมอ โดยไม่ต้องเขียน
   กฎเฉพาะให้บริษัทไหนเลย
3. ให้คะแนนทุกคู่ (คาบ, ห้อง) ที่ผ่านข้อจำกัดแข็ง แล้วเลือกคะแนนสูงสุด
   น้ำหนักทั้งหมดอยู่ใน `SCHEDULER_WEIGHTS` ที่เดียว
4. ถ้าวิชาไหนไม่มีที่ลง ลองย้ายวิชาที่กันอยู่ (เฉพาะที่ไม่ได้ล็อก) ลึกไม่เกิน 2 ชั้น
5. ถ้ายังไม่ได้ จะ **ไม่วางทับ** แต่รายงานพร้อมเหตุผลรายคาบและปุ่มทางออก

**การวางที่ผิดกติกาทำได้ แต่จะขึ้นเตือน** ผู้ใช้อาจรู้เรื่องที่ระบบไม่รู้ เช่น
บริษัทเพิ่งโทรมาบอกว่าสะดวกเพิ่ม ระบบที่ห้ามวางเลยคือระบบที่ถูกเลิกใช้

## ตรวจงาน

```bash
npm run check
```

รวมสี่อย่าง:

| คำสั่ง | ตรวจอะไร |
| --- | --- |
| `tsc --noEmit` | ชนิดข้อมูล |
| `npm run check:css` | รูปแบบที่เคยทำให้ `app/globals.css` พังมาแล้วจริง |
| `npm run check:pages` | ความสม่ำเสมอข้ามหน้า และคลาส CSS ที่ไม่มีใครใช้แล้ว |
| `npm run check:scheduler` | 12 เคสของอัลกอริทึมจัดตาราง |

`check:scheduler` รัน TypeScript ตรง ๆ ด้วย `node --experimental-strip-types`
ไม่มี build step และไม่มี test framework

## โครงสร้าง

```
app/                หน้าเว็บ (App Router) + globals.css
components/         UI ทั้งหมด — plan-shell คือกรอบที่ทุกหน้าใช้ร่วมกัน
lib/slots.ts        คำศัพท์คาบเรียนและเลขคณิตเวลา
lib/plan-types.ts   type ของโดเมนทั้งหมด
lib/plan-data.ts    จุดเดียวที่รู้ว่าข้อมูลมาจากไหน
lib/scheduler.ts    อัลกอริทึมจัดตาราง (pure)
lib/conflicts.ts    ตรวจแผนที่แก้มือแล้ว
lib/use-plan-state.ts  state + localStorage + undo
data/               ข้อมูลตั้งต้น
docs/data-model.md  เหตุผลเบื้องหลังโครงสร้างข้อมูล
docs/legacy/        สคีมาและข้อมูลของรุ่น dashboard เดิม
```

## ที่ยังไม่ได้ทำ

- ฐานข้อมูลจริง — ย้ายได้โดยแก้แค่ `lib/plan-data.ts`
- ผู้ใช้หลายคนพร้อมกัน — `localStorage` เป็นของเครื่องใครเครื่องมัน
- ปฏิทินรายสัปดาห์จริง (สัปดาห์ที่ 1–10, วันหยุด, ชดเชย)
- Export เป็น .xlsx / .ics
